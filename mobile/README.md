# REACT — Mobile App

React Native (Expo SDK 56) client for the REACT JITAI study.

macOS only for now. Nobody has run the Android or Windows setup yet.

## Backend setup

The app needs the backend running.

```bash
brew install postgresql@16 redis
brew services start postgresql@16
brew services start redis
export PATH="/opt/homebrew/opt/postgresql@16/bin:$PATH"   # add to ~/.zshrc
createdb react
```

Use Python 3.12. Django 5.1 doesn't support 3.14, and CI runs 3.11.

```bash
cd backend
/opt/homebrew/bin/python3.12 -m venv venv
source venv/bin/activate
pip install -r requirements_mac.txt
```

Create `backend/.env`:

```
SECRET_KEY=local-dev-only-not-a-real-secret
DEBUG=True
DATABASE_NAME=react
DATABASE_USER=<your macOS username>
DATABASE_HOST=localhost
DATABASE_PORT=5432
REDIS_URL=redis://localhost:6379/0
DASHBOARD_API_KEY=local-dev-key
JITAI_RANDOMIZATION_PROBABILITY=0.5
```

Use the separate `DATABASE_*` vars, not `DATABASE_URL`. `settings.py` forces `ssl_require=True`
for any `postgres://` URL and local Postgres has no SSL, so you get
`server does not support SSL, but SSL was required`.

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py test          # 194 tests
python manage.py runserver
```

Admin is at http://localhost:8000/admin.

## Mobile setup

Needs Node 22.13 or newer, Xcode, and CocoaPods.

```bash
cd mobile
npm install
npx expo run:ios
```

First run is 10-15 minutes while CocoaPods and the native build finish. After that it's quick.

Expo Go won't work. `android/` and `ios/` are committed so this is a bare-workflow project.
Use `run:ios` or `run:android`, not `expo start`.

Set `ACTIVE_ENV` to `'dev'` in `src/api/config.ts` to hit your local backend. Don't commit
that — it points production builds at localhost.

`dev` is `127.0.0.1:8000`. That works in a simulator but not on a real phone. On hardware use
your Mac's LAN IP from `ipconfig getifaddr en0` and add it to `ALLOWED_HOSTS`.

## Layout

```
index.ts            entry point
App.tsx             root, screen switching + push listeners
src/
  api/              config (BASE_URL), client (axios + auth), endpoints
  store/            authStore, zustand + SecureStore
  screens/          Login, Register, Compose
  components/       ComposeInput, NotificationToast
  telemetry/        keystroke counting, offline queue
  notifications/    Expo push token registration
android/  ios/      generated by expo prebuild, don't hand-edit
```

There's no router. Screens are a `useState` union in `App.tsx` with a ternary, so adding a
screen means extending that union. State is zustand.

Compose text never leaves the device. Only `keystroke_count`, `delete_count` and
`time_on_compose` get sent. Notification bodies aren't stored either, just a `prompt_id`.
That's an IRB requirement and it's enforced here in the client.


CI doesn't build the mobile app, so run these yourself.

## Known issues

The client calls `/auth/token/refresh/` and `/auth/me/`, which don't exist. The API contract
says there's no refresh — on a 401 you send the user back to login. So the fix is deleting
that logic from `client.ts`, not adding backend routes. Until then tokens die after 30
minutes and the UI still looks logged in while every request 401s. You'll hit this testing.

There's no EMA submission UI yet. `ema.submit()` exists in `endpoints.ts` and nothing calls it.

Push notifications need a physical device. `pushToken.ts` returns null on simulators.

Full list is in `../Resources/REACT_Mobile_App_Gaps.docx`.
